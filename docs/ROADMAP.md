## 阶段 A：桌面版与站点规则（P0，用户明确刚需）

### 0.30 桌面版模式 v2（单文档代理）
只改 UA 做不到——WebView 改不了 Client Hints，站点会把你 302 回移动版甚至死循环。
方案见 **[docs/DESKTOP_MODE.md](DESKTOP_MODE.md)**：主文档由 App 用 OkHttp 抓取并伪造全部 hint 头，再交给 WebView。

- 代理引擎：显式 `Sec-CH-UA-Mobile: ?0` / `Sec-CH-UA-Platform`，Cookie 双向同步，base 注入修相对路径
- 重定向由自己跟随（最多 5 跳，m./www 互换只允许 1 次）→ **物理上不可能无限循环**
- POST / 上传 / 非 HTML / 超大响应一律回退给 WebView
- 全局「始终请求桌面版」开关 + 站点级覆盖（强制桌面 / 强制移动 / 默认）
- 验收：B 站、知乎、豆瓣、微博一次加载即停在桌面布局，登录可用，失败不白屏

### 0.30.1 桌面版体验补完
- 桌面视口（1280 宽 + 缩放档）、UA 选择（macOS / Windows）
- 登录/支付类站点的"临时切回移动版"一键入口

## 常驻质量项（每版必须）

- 单测全绿（当前 67 条）、`lintDebug` 0 error、CI 绿
- release APK 必须能被 `aapt2` 解析（AGP 9 资源优化坑，见 HANDOFF）
- 文档同步：HANDOFF / TESTING / RELEASE_NOTES

## 明确不做

- 自研内核（GeckoView 已证伪，+100MB）
- VPN / MITM 全局代理（要装 CA、破坏信任链）
- 云端渲染、账号体系、资讯流
- 翻译功能（用户明确要求跳过）
